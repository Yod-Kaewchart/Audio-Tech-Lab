# ตั้งชื่อไฟล์ก่อนดาวน์โหลด — Audio Tech Labs Media Tools

วันที่ 8 ตุลาคม 2026 · สถานะ: สำรวจและออกแบบ ยังไม่เชื่อมกับโปรแกรมจริง

## ความต้องการที่ยืนยัน

ผู้ใช้ต้องการเปลี่ยนชื่อไฟล์ **ก่อนกดดาวน์โหลด** ออกแบบสำหรับ Download Audio ก่อน ไม่เพิ่มการเปลี่ยนชื่อไฟล์ที่บันทึกเสร็จแล้ว ขั้นตอนยังทำบนเครื่องผู้ใช้ทั้งหมด

## ผลสำรวจโปรแกรมปัจจุบัน

- `desktop/media-tools/ui/view.js`: ส่วน 02 มีรูปแบบ/คุณภาพเสียงและโฟลเดอร์ แต่ไม่มีช่องชื่อไฟล์
- `ui/controller.js`: ปุ่มเริ่มต้องมี source, folder, รูปแบบที่ผู้ใช้เลือก และเครื่องมือพร้อม; ส่งเฉพาะ sourceId, folderId, requestId และ encoding ไป native
- `src/common.cjs`: DTO ตรวจชื่อ field แบบ strict จึงเพิ่ม field ใหม่เฉพาะหน้าจอไม่ได้ ต้องปรับ validation ฝั่ง native ด้วย
- `src/engine.cjs`: ชื่อถูกสร้างหลัง probe ผลลัพธ์ โดยใช้ `cleanName(path.parse(source.dto.displayName).name)` แล้วเติม ` — download` หรือ ` — converted`
- `src/files.cjs`: cleanName ของชื่ออัตโนมัติแทนอักขระต้องห้ามด้วย `_`, ตัดท้ายจุด/ช่องว่าง และจำกัด 110 UTF-16 code units; ยังไม่มี validator สำหรับชื่อที่ผู้ใช้กรอก
- `native/ProcessHost.cs`: บันทึกผ่าน MoveFileEx โดยไม่เปิด flag เขียนทับ เมื่อชนชื่อจะกลับไปลองเลขท้าย `(1)` ถึง `(9999)` ใน engine; ควรใช้กระบวนการนี้ต่อ
- Original Audio ใช้นามสกุลจากไฟล์ที่ดาวน์โหลดจริง ส่วน MP3/WAV/FLAC/ALAC ใช้ `.mp3`/`.wav`/`.flac`/`.m4a`

ข้อควรแก้ระหว่างพัฒนา: ห้ามใช้ path.parse กับชื่อวิดีโอเพื่อหักนามสกุล เพราะ title เช่น `Lab Session Vol.1` อาจสูญเสีย `.1` แม้ไม่ได้เป็นชื่อไฟล์ สำหรับ Download ให้รักษา title เต็ม ส่วน Convert ที่เป็นไฟล์จริงค่อยหักนามสกุลจริงออก

## แบบหน้าจอที่เสนอ

ภายในส่วน **02 รูปแบบและปลายทาง** เรียงเป็น: รูปแบบเสียง → คุณภาพ → **ชื่อไฟล์ผลลัพธ์** → โฟลเดอร์ปลายทาง → **จะบันทึกเป็น** → ปุ่มดาวน์โหลด

| รายการ | พฤติกรรม |
| --- | --- |
| ชื่อไฟล์ผลลัพธ์ | ช่องข้อความบรรทัดเดียว รองรับภาษาไทย อังกฤษ ตัวเลข ช่องว่าง และ Unicode ที่ Windows รองรับ |
| ค่าเริ่มต้น | หลังตรวจลิงก์สำเร็จ เติมชื่อจากต้นทางที่ปรับให้ใช้บน Windows ได้แล้ว พร้อม ` — download` ตามพฤติกรรมเดิม ผู้ใช้แก้ชื่อทั้งหมดได้ |
| ก่อนตรวจลิงก์ | ช่องยังว่างและปิดใช้งาน ข้อความ “ตรวจสอบลิงก์ก่อนตั้งชื่อไฟล์” |
| นามสกุล | แสดงแยกด้านข้างแบบอ่านอย่างเดียว ตามรูปแบบที่เลือก ไม่ให้ผู้ใช้เปลี่ยนชนิดไฟล์ด้วยการแก้นามสกุล |
| ยังไม่เลือกรูปแบบ | แสดง “เลือกรูปแบบเสียง” และปุ่มดาวน์โหลดปิดอยู่ |
| Original Audio | แสดง “นามสกุลตามต้นทาง” ไม่สัญญาว่าเป็น `.webm` หรือ `.m4a` ก่อนมีไฟล์จริง |
| ใช้ชื่อต้นทาง | ปุ่มข้อความคืนชื่ออัตโนมัติ หากชื่อที่แก้ไว้ไม่ตรงกับค่าต้นทาง |
| จะบันทึกเป็น | อัปเดตชื่อพร้อมนามสกุลและโฟลเดอร์ทันทีตามข้อมูลที่ทราบ; ถ้ายังไม่เลือกโฟลเดอร์แสดงข้อความให้เลือก |
| ชื่อซ้ำ | ข้อความ “ชื่อซ้ำจะเติม (1), (2) … ไม่เขียนทับไฟล์เดิม” ชื่อใน preview เป็นชื่อที่ตั้งใจใช้ ไม่ใช่การจองชื่อ |

ตัวอย่าง: ผู้ใช้กรอก `สัมภาษณ์ EP 01` และเลือก MP3 → แสดง `สัมภาษณ์ EP 01.mp3` ถ้ามีชื่อเดียวกันตอนบันทึกจริง → บันทึก `สัมภาษณ์ EP 01 (1).mp3` และแสดงชื่อจริงในส่วน 03

## กฎการกรอกชื่อ

1. ใช้เฉพาะชื่อ ไม่รับ drive, folder หรือ path; นามสกุลถูกเติมโดยโปรแกรม
2. ช่องว่างทั้งหมดหรือชื่อว่าง: แสดง “กรุณาตั้งชื่อไฟล์ หรือกดใช้ชื่อต้นทาง” และปิดปุ่มดาวน์โหลด
3. อักขระต้องห้าม `< > : " / \ | ? *` และ control characters: แสดงข้อผิดพลาดใต้ช่อง ปิดปุ่มดาวน์โหลด ไม่แก้ชื่อที่ผู้ใช้ตั้งให้เงียบ ๆ
4. ชื่อสงวน Windows เช่น CON, PRN, AUX, NUL, COM1–9, LPT1–9 และรูปแบบเลขยกกำลัง ¹/²/³: ปฏิเสธ รวมชื่อที่มีจุดต่อท้าย เช่น `CON.audio`
5. ช่องว่างหัว/ท้ายปรับให้เห็นเมื่อออกจากช่อง และ normalize Unicode เป็น NFC; จุดท้ายชื่อให้ผู้ใช้แก้เอง ชื่อ `.` และ `..` ใช้ไม่ได้
6. ชื่อที่ผู้ใช้กรอกยาวเกินขีดจำกัดแอป 110 UTF-16 code units: ให้ย่อชื่อ ไม่ตัดเอง ค่า 110 เป็นนโยบายแอปเดิม ไม่ใช่เพดานของ Windows ทุกเครื่อง
7. หากพิมพ์นามสกุลเสียงที่รู้จัก เช่น `.mp3` หรือ `.wav` มาด้วย ให้แจ้ง “ใส่เฉพาะชื่อ โปรแกรมเติมนามสกุลให้เอง” และให้แก้ก่อนเริ่ม ไม่เสี่ยงเปลี่ยนความหมายของชื่อด้วยการตัดอัตโนมัติ จุดภายในชื่อทั่วไป เช่น `Mix v1.2` ยังใช้ได้
8. ตรวจ path เต็มอีกครั้งหลังเลือกโฟลเดอร์ โดยเผื่อเลขท้ายชนชื่อและนามสกุลจริงด้วย ข้อเสนอรุ่นแรกใช้เพดานอนุรักษนิยม 259 UTF-16 code units ไม่รวม NUL และตรวจ path ของ staging ด้วย ต้องตรวจรับกับ helper/worker จริงก่อนยืนยันว่าเพิ่ม long-path ได้

อักขระและชื่อสงวนอ้างอิง [Microsoft: Naming Files, Paths, and Namespaces](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file) ส่วนการรองรับ long-path ต้องขึ้นกับระบบและแอปตาม [Maximum Path Length Limitation](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation) ข้อจำกัดแอปที่เสนออาจเข้มกว่า Windows

## การเปลี่ยนสถานะ

- ตรวจลิงก์ใหม่สำเร็จ: เติมชื่อจากต้นทางรายการใหม่ ไม่ยกชื่อที่ผู้ใช้แก้ให้รายการเก่ามาใช้กับรายการใหม่
- แก้ URL: ยกเลิก source เดิมและปิดปุ่มดาวน์โหลด เก็บชื่อร่างไว้ให้เห็นแต่ปิดช่องไว้จนตรวจใหม่; เมื่อ source ใหม่สำเร็จเติมชื่อใหม่
- เปลี่ยนรูปแบบ: เก็บชื่อที่ตั้งไว้ อัปเดตเฉพาะนามสกุลและคุณภาพ
- เปลี่ยนโฟลเดอร์: เก็บชื่อ อัปเดต preview และตรวจความยาว path ใหม่
- ระหว่างทำงาน: ล็อกชื่อ/รูปแบบ/ปลายทาง ใช้ชื่อที่จับไว้ตอนกดเริ่ม แม้สลับหน้า
- ล้มเหลวหรือยกเลิกครบแล้ว: กลับมาแก้ชื่อและลองใหม่ได้ การแก้ชื่อทำให้ต้องสร้าง requestId ใหม่
- Reload/เปิดแอปใหม่: งานปัจจุบันยังแสดง snapshot เดิม ส่วนงานใหม่ต้องตรวจลิงก์ใหม่ก่อนตั้งชื่อ ไม่เพิ่มระบบจำชื่อข้าม session ในรอบนี้

## แผนเชื่อมต่อเมื่อสั่งพัฒนา

เพิ่ม `outputName: string` ในคำขอ **startDownload เท่านั้น** โดยหมายถึง base name ที่ไม่มี extension ใช้ค่าที่เห็นในช่องทั้งกรณีชื่ออัตโนมัติและชื่อที่ผู้ใช้แก้ ไม่รับ full path และไม่เปลี่ยน DTO ของ Convert ในรอบนี้

ตัวอย่างเฉพาะ field ใหม่: `outputName: "สัมภาษณ์ EP 01"` ค่า folder ยังคงอ้างด้วย folderId ไม่ได้มาจากช่องชื่อไฟล์

| ส่วน | งานที่ต้องทำ |
| --- | --- |
| View / prepare-ui | เพิ่มช่อง ชื่อนามสกุลอ่านอย่างเดียว ปุ่มคืนชื่อ ข้อผิดพลาด และ preview; อัปเดตตัวสร้างหน้าจอให้ build ใหม่แล้วไม่หาย |
| Controller | เก็บ draft name, validate, อัปเดต preview, เพิ่ม nameValid ในเงื่อนไข Start/Retry, reset requestId เมื่อแก้ชื่อ และส่ง outputName |
| Common / naming rules | ใช้กฎร่วมที่ทดสอบได้ระหว่าง UI/native; native ตรวจซ้ำทุกคำขอ ก่อนตั้ง job หรือเรียก worker ห้ามเชื่อผลจาก UI อย่างเดียว |
| Main / preload | ใช้ startDownload เดิม ไม่เพิ่มสิทธิ์อ่านเขียนไฟล์หรือ API rename ถ้ามีไฟล์กฎใหม่สำหรับ renderer เพิ่มเฉพาะไฟล์นั้นใน protocol allowlist |
| Engine | จับ outputName ที่ตรวจแล้วใน snapshot ตั้งแต่เริ่ม; นำไปใช้เฉพาะ publish ขั้นสุดท้าย ไม่ใส่ใน argv ของ yt-dlp/FFmpeg หรือชื่อ staging |
| Contract | แยก DownloadStartRequest ที่มี outputName; อัปเดต snapshot ให้แสดงชื่อที่ตั้งไว้ขณะทำงาน; Convert คงรูปแบบคำขอเดิม |
| Save/result | ใช้ publish แบบไม่เขียนทับเดิม เก็บ output.fileName/displayPath จากชื่อที่บันทึกจริง รวมเลขท้ายและนามสกุล |

staging ยังคงใช้ชื่อภายใน `source.<ext>` และ `output.<ext>` ไม่ใช้ชื่อจากผู้ใช้ ไม่เปลี่ยนต้นฉบับ ไม่เพิ่มข้อมูลชื่อไฟล์หรือไฟล์สื่อบน Server ของ Audio Tech Labs

## ตรวจรับก่อนส่งรุ่นทดลองใหม่

- Source/โฟลเดอร์/รูปแบบครบแต่ชื่อว่างหรือผิดกฎ: Start/Retry ปิด; คำขอ native ที่ข้าม UI ถูกปฏิเสธก่อนมี worker
- ชื่อไทย อังกฤษ Unicode จุดภายในชื่อ และชื่อที่ขอบเขตความยาว บันทึกได้ตรง preview; ไม่ตัดสระ/วรรณยุกต์หรือ surrogate pair ระหว่างเตรียมชื่ออัตโนมัติ
- ทั้งห้ารูปแบบ Download ใช้นามสกุลจริง MP3/WAV/FLAC/ALAC ไม่ซ้ำ extension; Original ไม่ hardcode container
- ชื่อซ้ำและมี writer อีกตัวสร้างชื่อระหว่างตรวจ/บันทึก: ไฟล์เดิมไม่เปลี่ยน ผลลัพธ์มีเลขท้ายที่ถูกต้อง
- เปลี่ยนรูปแบบ/โฟลเดอร์/ต้นทาง, คืนชื่อต้นทาง, cancel/retry, page navigation และ requestId reuse ได้ผลตามกฎ
- ชื่อผลลัพธ์ของ Convert และไฟล์ต้นฉบับยังถูกเก็บรักษา; ไม่มีเส้นทาง rename ไฟล์สำเร็จในรอบนี้
- 360/768/1440px, keyboard, ภาษาไทยยาว, aria-invalid/ข้อความแจ้ง และ native portable ถูกตรวจครบ

## ต้นแบบประกอบ

`preview.html`, `preview.css`, `preview.js` เป็น mock ของส่วน 01/02 ใช้ CSS/ฟอนต์เดิมของ Media Tools วาง URL YouTube แล้วตรวจเฉพาะรูปแบบข้อความในเครื่องเพื่อเปิดช่องชื่อไฟล์ได้ มีปุ่มใช้ลิงก์ตัวอย่าง ชื่อวิดีโอเป็นข้อมูลจำลองเสมอ ไม่ติดต่อ YouTube/yt-dlp ไม่มี native bridge ไม่มีการดาวน์โหลด แปลง หรือบันทึกไฟล์ กฎใน mock มีไว้สาธิต ยังไม่ใช่ production validator

ยังไม่ได้แก้โค้ดโปรแกรมจริง สร้าง portable ใหม่ หรือเปลี่ยนโปรแกรมที่ผู้ใช้เปิดอยู่
