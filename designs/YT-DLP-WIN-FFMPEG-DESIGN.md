# Audio Tech Labs — yt-dlp_win + FFmpeg

ฉบับออกแบบ 8 ตุลาคม 2026 · ยังไม่เริ่มพัฒนาระบบจริง

**อ้างอิงรุ่นล่าสุด:** ต้นแบบที่สร้างแล้วใช้สองหน้า Download / Convert และ “งานปัจจุบัน” ครั้งละหนึ่งรายการ ตาม `media-tools/README.md` แนวคิดคิวหลายงานและ layout alternatives ในเอกสารฉบับนี้เป็นข้อเสนอเดิม สำหรับงานเชื่อมต่อให้ยึด [Local connection readiness](media-tools/connection/README.md) และสัญญาการเชื่อมต่อในโฟลเดอร์เดียวกันเป็นหลัก

## แนวทางที่เสนอ

ชื่อภายในโครงการ: `yt-dlp_win` ชื่อที่ผู้ใช้เห็น: **Media Tools** แบ่งเป็น **Download Audio** และ **Convert Audio** ใช้คิวงานในเครื่องผู้ใช้ เริ่มจากลิงก์หรือไฟล์ในเครื่อง แล้วบันทึกผลลงโฟลเดอร์ที่ผู้ใช้เลือก

**ข้อกำหนดที่ผู้ใช้ยืนยัน:** ไฟล์ปลายทางต้องอยู่ที่เครื่องผู้ใช้เอง จึงปรับทั้งการตรวจลิงก์ ดาวน์โหลด แปลง ตรวจไฟล์ และคิวงานให้ทำงานในเครื่องผู้ใช้ ต้นทางสื่อเชื่อมตรงกับเครื่องผู้ใช้ การวางไฟล์ปลายทางไว้ในเครื่องผู้ใช้เพียงอย่างเดียว แต่ยังดาวน์โหลดหรือแปลงบน Server ไม่ตรงกับแนวทางนี้

รูปแบบที่เสนอให้ทำได้จริงคือ **โปรแกรม Windows บนเครื่องผู้ใช้** ซึ่งเรียก yt-dlp.exe, FFmpeg และ FFprobe ภายในเครื่อง เว็บไซต์ Audio Tech Labs ใช้แนะนำและแจกโปรแกรม โมดูลนี้ไม่มีการส่งลิงก์ ไฟล์สื่อ ประวัติคิว หรือการประมวลผลเข้า Server ของ Audio Tech Labs

หากภายหลังต้องการควบคุมจากหน้าเว็บ ให้ใช้ companion ที่ติดตั้งในเครื่องผู้ใช้เป็นทางเลือกแยก ต้องออกแบบการจับคู่และการอนุญาต origin ก่อน เอกสารนี้เลือกหน้าตาแอป Windows เป็นฐานการออกแบบ เพราะเบราว์เซอร์ทั่วไปเรียก executable ของ Windows โดยตรงไม่ได้ ส่วนการทำ FFmpeg ในเบราว์เซอร์เป็นอีกแนวทางหนึ่งซึ่งยังไม่อยู่ในขอบเขต

นี่คือการตัดสินใจเรื่องตำแหน่งการทำงานและการเก็บไฟล์ ไม่ใช่ข้อสรุปเกี่ยวกับสิทธิ์ของสื่อ

รอบนี้ส่งเฉพาะแนวทางและต้นแบบหน้าจอ ข้อมูลในต้นแบบเป็นตัวอย่างสมมติ ไม่มีการเรียก yt-dlp / FFmpeg ไม่มีการติดตั้งเครื่องมือหรือเปลี่ยนบริการและหน้าเว็บจริง

## หน้าจอและลำดับใช้งาน

### Download Audio

1. วางลิงก์หนึ่งรายการ แล้วกด **ตรวจสอบลิงก์**
2. แสดงชื่อรายการ ระยะเวลา ผู้เผยแพร่ codec / container และข้อมูลคุณภาพที่ต้นทางให้มา ใช้ “ไม่ทราบ” เมื่อไม่มีข้อมูล ไม่สร้าง bit depth หรือ bitrate ขึ้นเอง
3. เลือกรูปแบบปลายทางและ **โฟลเดอร์ปลายทางในเครื่อง** ดูสรุปผล แล้วกด **เพิ่มเข้าคิว**
4. แสดงสถานะ รอคิว → ดาวน์โหลด → เตรียมเสียง → ตรวจสอบไฟล์ → พร้อมใช้งาน
5. ไฟล์พร้อมใช้งานอยู่ในเครื่องแล้ว กด **เปิดโฟลเดอร์** หรือ **เปิดไฟล์** ไม่ต้องดาวน์โหลดกลับจาก Server อีกครั้ง

หากลิงก์เปลี่ยน ต้องล้างข้อมูลการตรวจสอบเดิมและปิดปุ่มเพิ่มเข้าคิวจนตรวจสอบใหม่ ห้ามใช้ชื่อหรือ format จากลิงก์ก่อนหน้า

### Convert Audio

1. เลือกไฟล์เสียงหนึ่งไฟล์
2. FFprobe ในเครื่องอ่านไฟล์โดยตรง แสดง codec ระยะเวลา sample rate ช่องเสียง และ bit depth เมื่อทราบ
3. เลือก MP3 / WAV / FLAC / ALAC พร้อมค่าที่เกี่ยวข้องและโฟลเดอร์ปลายทาง แล้วกด **เพิ่มเข้าคิว**
4. แสดงสถานะ รอคิว → แปลงเสียง → ตรวจสอบไฟล์ → พร้อมใช้งาน

เลือกไฟล์ด้วยหน้าต่างของ Windows และใช้ไฟล์ในเครื่องโดยตรง ไม่มีขั้นตอน Upload เก็บต้นฉบับไว้และสร้างไฟล์ผลลัพธ์ใหม่ ไม่เขียนทับต้นฉบับ

### โฟลเดอร์ปลายทาง

- แสดงปลายทางก่อนเริ่มงาน ปุ่ม **เลือกโฟลเดอร์** เปิด native folder picker เมื่อพัฒนาจริง
- เสนอค่าเริ่มต้นเป็นโฟลเดอร์ Audio Tech Labs ภายใน Downloads ที่ระบบ Windows resolve จริง ไม่ hardcode ชื่อผู้ใช้หรือ drive
- ตรวจสิทธิ์เขียน พื้นที่ว่าง และชื่อไฟล์ก่อนเริ่ม เก็บไฟล์ชั่วคราวใน staging ของงานบนเครื่องเดียวกัน
- ชื่อซ้ำให้สร้างชื่อใหม่หรือถามผู้ใช้ ไม่เขียนทับอัตโนมัติ เปลี่ยนโฟลเดอร์ในหน้าตั้งค่าส่งผลกับงานใหม่เท่านั้น งานที่เข้าคิวแล้วเก็บปลายทางของตนเอง

### คิวและผลลัพธ์

- แสดงงานของ Windows user ปัจจุบัน: ชื่อไฟล์ รูปแบบ โฟลเดอร์ปลายทาง ขั้นตอนปัจจุบัน และการกระทำที่ใช้ได้ คิวเก็บบนเครื่องผู้ใช้ ไม่ใช้คิว Server เดิม
- ขณะดาวน์โหลดแสดงเปอร์เซ็นต์เมื่อมีจำนวนไบต์รวมจริง หากไม่ทราบแสดงจำนวนที่รับแล้ว ขณะ FFmpeg ทำงานใช้เวลาเสียงที่ประมวลผลเทียบกับระยะเวลาเมื่อทราบ
- ดาวน์โหลดถึง 100% ยังไม่เท่ากับงานสำเร็จ ต้องจบขั้นตอนแปลงและตรวจสอบไฟล์ก่อน
- **ยกเลิก** ใช้ได้ระหว่างรอและทำงาน ผลลัพธ์ที่ยังไม่สมบูรณ์ไม่ปรากฏเป็นไฟล์พร้อมใช้งาน
- **ลองใหม่** สร้างงานใหม่ ไม่เปลี่ยนสถานะงานที่ล้มเหลวในประวัติ
- **เปิดโฟลเดอร์** และ **เปิดไฟล์** ใช้ได้เมื่อผลลัพธ์เสร็จและไฟล์ยังอยู่จริง
- ไฟล์ผลลัพธ์ไม่มีวันหมดอายุและไม่ถูกลบอัตโนมัติ การเอารายการออกจากประวัติไม่ลบไฟล์ผลลัพธ์
- ปิดโปรแกรมต้องแจ้งงานที่กำลังทำและให้เลือกทำต่อหรือยกเลิก เปิดใหม่ไม่เริ่มดาวน์โหลดคิวที่ค้างโดยอัตโนมัติ ต้องให้ผู้ใช้กดเริ่มต่อ

## รูปแบบและคุณภาพ

| Preset | ใช้เมื่อ | พฤติกรรมที่ออกแบบ |
| --- | --- | --- |
| Original audio | เก็บเสียงต้นทาง | ดาวน์โหลด audio stream ที่เลือกและคง codec เดิม ไม่บังคับให้ทุกไฟล์เป็น M4A; remux ได้เมื่อ container รองรับ |
| MP3 | ใช้กับอุปกรณ์ทั่วไป | เลือก 128 / 192 / 256 / 320 kbps; เสนอค่าเริ่มต้น 192 kbps; เป็นการเข้ารหัสแบบ lossy |
| WAV | ส่งต่อไปแก้ไขเสียง | PCM 16 หรือ 24 bit; ค่าเริ่มต้น 16 bit; sample rate ตามต้นทางหรือเลือก 44.1 / 48 kHz |
| FLAC | เก็บผลแปลงในรูปแบบ lossless | PCM 16 หรือ 24 bit; ค่าเริ่มต้น 16 bit; sample rate ตามต้นทางหรือเลือก 44.1 / 48 kHz |
| ALAC (.m4a) | งานที่ใช้ ALAC | เข้ารหัส ALAC ภายใน M4A; ต้องแยกจาก AAC ที่อยู่ใน M4A เช่นกัน |

ข้อความข้าง preset WAV / FLAC / ALAC: **“การแปลงเป็น lossless ไม่ได้เพิ่มรายละเอียดที่ต้นทางไม่มี”** ไม่ใช้คำว่า Hi-Res หรือ Studio Master เพียงเพราะปลายทางเป็น 24 bit ไม่ resample หรือเพิ่ม bit depth อัตโนมัติ

Original audio ใช้เฉพาะ Download รุ่นแรก ส่วน Convert ต้องเลือกรูปแบบปลายทางที่ชัดเจน รุ่นแรกไม่มีปุ่มส่งต่อเข้า Web Demo โดยอัตโนมัติ ผู้ใช้เปิดไฟล์ในเครื่องมือภายในเครื่องที่รองรับได้เอง การเชื่อมกับ Split / Merge / QC แบบ local เป็นงานแยกในอนาคต

## งานออกแบบภาพ

- สืบทอดแบรนด์ Audio Tech Labs: พื้นเข้ม สีทองสำหรับปุ่มหลัก และเส้นแบ่งบาง; รองรับ appearance ของหน้าพรีวิวโดยมีสีที่สอดคล้องกันในโหมดสว่าง
- **Workspace**: แหล่งเสียงด้านซ้าย รูปแบบปลายทางด้านขวา คิวอยู่ด้านล่าง เหมาะกับการเห็นทุกค่าก่อนเริ่ม
- **Focus**: แหล่งเสียงและรูปแบบเรียงตามลำดับ คิวอยู่ข้างพื้นที่ทำงาน เหมาะกับการติดตามงานต่อเนื่อง
- เมื่อหน้าต่างแคบเรียงแหล่งเสียง → รูปแบบและโฟลเดอร์ → คิว ใช้ปุ่มสัมผัสอย่างน้อย 44px ชื่อไฟล์ภาษาไทยและชื่อยาวตัดบรรทัดได้ หน้าพรีวิวดูบนมือถือได้ แต่ไม่ได้หมายความว่า executable ของ Windows ทำงานบนมือถือ
- ซ่อนค่าเพิ่มเติมที่ยังไม่จำเป็น; ไม่แสดง raw command line หรือที่อยู่โปรแกรมในหน้าทำงานทั่วไป

## โครงสร้างสำหรับการพัฒนาในภายหลัง

แบ่งหน้าที่ภายในเครื่องผู้ใช้เป็น **Windows UI → local application service → local queue → media runner → โฟลเดอร์ปลายทาง** ต้นทางสื่อ → yt-dlp ในเครื่องผู้ใช้ → staging ในเครื่อง → FFmpeg / FFprobe ในเครื่อง → ไฟล์ผลลัพธ์ในเครื่อง ไม่มี Server ของ Audio Tech Labs อยู่ในเส้นทางสื่อหรือคิว

รุ่นแรกเสนอประมวลผลครั้งละหนึ่งงานในเครื่อง เพื่อจำกัดการแย่ง CPU / disk คิวนี้แยกจาก processing queue ของ Web Demo ไม่แชร์บัญชีฐานข้อมูลหรือโควตา Server

| ส่วน | หน้าที่ |
| --- | --- |
| yt-dlp.exe | อ่านข้อมูลต้นทาง เลือก format ดาวน์โหลด audio stream และรายงานความคืบหน้าแบบโครงสร้าง |
| ffmpeg.exe | แยกเสียง remux หรือแปลง codec ตาม preset |
| ffprobe.exe | ตรวจเนื้อหาไฟล์ก่อนและหลังทำงาน |
| JS runtime + EJS | dependency สำหรับการรองรับ YouTube ของ yt-dlp รุ่นปัจจุบัน |

เสนอแจก executable ที่ pin รุ่นพร้อมโปรแกรมหรือให้ setup ดาวน์โหลด dependency จากผู้เผยแพร่ลงเครื่องผู้ใช้โดยตรง ระบุ absolute path จาก configuration เก็บ version / checksum และทดสอบก่อนสลับรุ่น มี rollback ไม่อัปเดต binary ระหว่างงาน ผู้ใช้ทั่วไปไม่ต้องจัดการ path ของโปรแกรม การอัปเดตโปรแกรมเป็นคนละช่องทางกับข้อมูลลิงก์ ไฟล์ และคิว

เอกสารปัจจุบันแนะนำ `yt-dlp.exe` สำหรับ Windows x64 และระบุว่า FFmpeg / FFprobe จำเป็นกับการแยกเสียงหรือ post-processing บางประเภท การรองรับ YouTube เต็มรูปแบบต้องมี EJS และ JS runtime ด้วย จึงไม่ควรออกแบบ readiness ให้ตรวจแค่สาม executable ดู [yt-dlp dependencies](https://github.com/yt-dlp/yt-dlp#dependencies) และ [EJS setup](https://github.com/yt-dlp/yt-dlp/wiki/EJS) — EJS รวมอยู่ใน official executable แต่ runtime ต้องตรวจและเปิดใช้งานอย่างชัดเจน

Original audio ต้องแยก stream copy ออกจากการเข้ารหัสใหม่ เพราะ stream copy คง packets โดยไม่ decode / encode และมีข้อจำกัดตาม container ดู [FFmpeg streamcopy](https://ffmpeg.org/ffmpeg.html#Streamcopy) ใช้ [FFprobe](https://ffmpeg.org/ffprobe.html) ตรวจผลลัพธ์จริง

### ข้อกำหนดของ local runner

- เรียก executable ด้วย argument array และไม่ผ่าน shell ใช้ preset ที่ allowlist ไม่รับ custom command หรือ postprocessor จากลิงก์ ตำแหน่งไฟล์มาจาก native folder picker
- metadata inspection และการดาวน์โหลดทำจากเครื่องผู้ใช้โดยตรง รุ่นแรกรับลิงก์ HTTPS ของ provider ที่กำหนด ไม่ดึง browser cookies โดยอัตโนมัติ
- รุ่นแรก: ลิงก์สาธารณะหนึ่งรายการ ไม่ใช้ playlist, live stream, cookies, proxy หรือ plugin ที่ผู้ใช้ส่งมา
- ใช้ output path ภายใต้โฟลเดอร์ที่ผู้ใช้เลือก ตรวจ path containment ไม่ใช้ชื่อจากต้นทางเป็น directory และไม่อ่าน path ของ Windows user อื่นเป็นค่าเริ่มต้น
- ใช้ structured progress ของ yt-dlp และ FFmpeg แทนการ parse ข้อความ console ปกติ
- กำหนด timeout และเพดานใช้พื้นที่แบบ local จากข้อมูลและพื้นที่ว่างจริง ไม่สืบทอดขีดจำกัด 2,000 MB / 30 นาที / อายุ 59 นาทีจากเว็บโดยอัตโนมัติ ต้องเผื่อ source + output + staging
- จัดการ process tree บน Windows รวม FFmpeg ที่ yt-dlp เรียก ต้องรายงาน cleanup failure และปิดการเริ่มงานถัดไปจนมั่นใจว่า process เดิมหยุดแล้ว ออกแบบ runner แยก; ใช้ปัญหา cleanup เดิมใน AUDIT-CHECKPOINT-20261008.md เป็นกรณีทดสอบอ้างอิง
- บันทึกผลลงที่เก็บจริงเมื่อ FFprobe ตรวจผ่านเท่านั้น ไฟล์ .part และไฟล์ผิดพลาดอยู่ใน staging และ cleanup ตามนโยบาย
- ประวัติและคิวเก็บใน local app data ของ Windows user ไม่มีการ sync ลิงก์หรือประวัติเข้า Server ไม่ลบไฟล์ผลลัพธ์เมื่อ clear history

## ขอบเขตรุ่นแรกที่เสนอ

โปรแกรม Windows: Download เสียงหนึ่งรายการ + Convert ไฟล์หนึ่งไฟล์, preset 5 แบบด้านบน, เลือกโฟลเดอร์ปลายทาง, คิว local, cancel / retry, เปิดโฟลเดอร์ / เปิดไฟล์ เลื่อน playlist / batch / วิดีโอ / subtitle / cookies / normalize / trim และการเชื่อมเครื่องมืออื่นไปหลังยืนยันรุ่นแรก

ข้อกำหนดที่ชัดแล้วคือสื่อและคิวอยู่ในเครื่องผู้ใช้เอง ก่อนเริ่มพัฒนาค่อยเลือก packaging ของโปรแกรม (portable หรือ installer), provider รุ่นแรก และค่าเริ่มต้นของ preset ต้นแบบใช้ Original audio สำหรับ Download และ FLAC สำหรับ Convert เป็นข้อเสนอเท่านั้น

## การตรวจรับเมื่อเริ่มพัฒนา

ใช้ไฟล์และลิงก์ทดสอบที่ได้รับอนุญาต ตรวจ codec / duration / frames; streamcopy ต้องคง audio stream ส่วน lossy conversion ไม่ใช้ PCM hash equality เป็นเกณฑ์ ทดสอบ local queue, ยกเลิกและ process-tree cleanup, ไม่มีพื้นที่, dependency หาย, link เปลี่ยน, ชื่อไทย, โฟลเดอร์ read-only / ชื่อซ้ำ / drive หลุด, เก็บปลายทางของงานเดิมเมื่อเลือกโฟลเดอร์ใหม่, ปิดและเปิดโปรแกรม และไฟล์ถูกย้ายหรือลบ ต้องตรวจ network ว่าไม่มีไฟล์ ลิงก์ หรือข้อมูลคิวส่งไป Server ของ Audio Tech Labs

การตรวจต้นแบบรอบนี้ยืนยันได้เฉพาะการจัดหน้าจอและการโต้ตอบจำลอง ไม่ยืนยันการทำงานของ provider, binary หรือระบบประมวลผลจริง
