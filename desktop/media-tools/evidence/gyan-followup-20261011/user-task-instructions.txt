3. อัปเดต inventory ตามขอบเขตที่ยืนยันจริง

- เลื่อน repository/commit ของ libxml2 และ zlib-ng จาก candidate เป็น publisher-confirmed

- “Vanilla cmake” ไม่ใช่การยืนยันทุก feature flag หรือประกาศว่า source ไม่มี patches ทั้งหมด
- อย่าถือว่า package dependencies ทุกตัวถูก linked เข้า binary จริง
- ทบทวนว่า GMP Mercurial metadata ยังจำเป็นหรือไม่ หากหลักฐานชี้ว่าใช้ MSYS2 recipe กับ release tarball

4. ปรับเกณฑ์ source review ให้ตรงความจำเป็น

อ่านแหล่งทางการ:
- https://www.gnu.org/licenses/gpl-3.0.html
- https://www.gnu.org/licenses/gpl-faq.en.html#MustSourceBuildToMatchExactHashOfBinary

แยกแต่ละช่องว่างเป็น:
A. Source/patches/scripts หรือ build inputs ที่จำเป็นสำหรับ corresponding source
B. หลักฐาน audit/reproducibility เพิ่มเติม เช่น ephemeral logs หรือ compiler snapshot
C. สิ่งที่ยังไม่ทราบ ต้องตรวจเพิ่มก่อนจัดประเภท

GPL ไม่กำหนดว่า rebuild ต้องได้ SHA256 เหมือน binary เดิมทุกบิต อย่าถือว่าขาด logs ทุกไฟล์แล้วเป็นข้อผิดพลาดด้าน license โดยอัตโนมัติ และอย่าถือว่าความเห็นของผู้เผยแพร่ทำให้ source gate PASS

ตรวจว่า instructions และ recipes ที่มีอยู่ครอบคลุมการสร้างจาก source จริงเพียงใด พร้อมระบุช่องว่างเฉพาะเจาะจง อย่าตัดรายการ scripts ที่จำเป็นออกเพียงเพราะเรียกว่า audit

ประเมิน FFmpeg และ yt-dlp แยกกัน อย่าให้คำตอบ Gyan ปิดช่องว่างของ yt-dlp หากหลักฐานยังไม่ครบ ให้คง source gate BLOCKED / INCOMPLETE พร้อมเหตุผลที่ปรับแล้ว

5. จัดเอกสารและตรวจความสอดคล้อง

เพิ่ม evidence รอบใหม่ในโฟลเดอร์ที่เหมาะสม อัปเดตรายงานรวม, inventory, closure plan และสถานะ follow-up ให้สอดคล้องกัน เก็บร่างเดิมและประวัติไว้ หากระบุการส่ง follow-up ให้ใช้ user-provided evidence และไม่สร้างหลักฐานส่งเพิ่มเติม

ตรวจ JSON, local links, hashes ของหลักฐานที่เพิ่ม/อ้างอิง และ diff ให้ผ่าน งานรอบนี้เป็นเอกสาร/หลักฐาน จึงใช้ checks ที่ตรงกับการเปลี่ยนแปลง ไม่ต้องเปิดแอปหรือรัน playback tests ซ้ำโดยไม่มีเหตุผล

6. Commit และเก็บออนไลน์

ตรวจ staged diff แล้ว commit เฉพาะไฟล์ของงานนี้ เช่น:
`docs(media-tools): record Gyan follow-up and refine source review`

ตรวจ URL ของ private-backup และยืนยันว่า repository ยังเป็น private ก่อน push branch ปัจจุบัน จากนั้นตรวจ local/remote commit ตรงกัน และรายงาน Git status จริง

ห้าม push branch นี้ไป public origin ห้าม force push, merge main, สร้าง release, deploy หรือเผยแพร่ screenshots/review kit สู่สาธารณะ หากยืนยันปลายทาง private ไม่ได้ ให้เก็บ local commit และรายงานสาเหตุที่ push ไม่สำเร็จ

ข้อจำกัด:
- ไม่เปลี่ยน binaries, dependencies, vendor, version หรือ runtime code
- ไม่ rebuild, reinstall หรืออัปเกรด FFmpeg เป็น 9.1
- ไม่แก้ข้อมูลผู้ใช้หรือ shortcuts
- ไม่ส่งอีเมลหรือเปิด issue
- คง Portable taskbar PASS และ gate อื่นตามหลักฐานเดิม

รายงานจบงาน: สิ่งที่ยืนยันเพิ่ม, ช่องว่างที่เหลือพร้อมประเภท A/B/C, source gate ล่าสุด, ไฟล์ที่เปลี่ยน, ผล validation, commit hash, ผล private push และ Git status
